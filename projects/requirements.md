# 基于特征工程的烘焙产品购买数量预测与回归模型比较

*Feature Engineering for Bakery Purchase Quantity Prediction: A Comparative Study of Regression Models*
**核心任务：** 根据订单发生时能够获得的商品、客户、价格、时间和环境信息，预测一条订单明细中某种商品的购买数量（Quantity）。

**拓展方向：** 特征工程与特征选择。

**主要方法：** Ridge Regression、Decision Tree、Random Forest。

**数据集：** Kaggle Historical Bakery Sales Dataset。

## 一、课题选择与研究问题

### 1.1 研究背景

烘焙零售业务中，不同商品、客户群体、价格策略、促销活动和时间环境可能影响消费者的购买数量。

例如：

- 周末是否会增加消费者的购买数量？
- 不同客户群体是否具有不同的购买偏好？
- 价格、折扣是否会影响购买数量？
- 天气和节日是否会影响商品购买行为？
- 哪些特征对购买数量预测最有价值？

本项目将其建模为一个监督学习回归问题：
$$
\hat{y}=f(X)
$$
其中：

- \(X\)：订单发生时可获得的特征。
- \(y\)：订单明细中某种商品的购买数量（Quantity）。
- \(f\)：待训练的回归模型。

### 1.2 具体研究问题

建议围绕四个问题组织实验：

| 编号 | 研究问题 | 对应实验 |
| --- | --- | --- |
| RQ1 | 不同经典回归算法的预测性能有何差异？ | 模型比较 |
| RQ2 | 时间、商品、客户、价格等特征分别贡献多大？ | 特征消融 |
| RQ3 | 特征组合、特征交互和特征选择能否提升性能？ | 特征工程 |
| RQ4 | 模型复杂度与泛化能力之间存在什么关系？ | 参数优化 |

## 二、数据集审计与预测目标

### 2.1 数据集基本情况

| 数据项 | 数值 |
| --- | ---: |
| 数据记录数 | 19,321 |
| 原始字段数 | 40 |
| 唯一订单数 | 6576 |
| 覆盖天数 | 731 |

| 数据属性 | 实际情况 |
| --- | --- |
| 时间跨度 | 2023-01-01 至 2024-12-31 |
| 客户数量 | 500 |
| 商品种类 | 35 |
| 门店数量 | 3 |
| 缺失字段 | Festival、Promotion_Type |
| 完全重复记录 | 0 |

数据集具有以下特点：

1. 数值特征与类别特征混合，适合研究不同编码和预处理方式。
2. 商品类别较丰富，适合研究类别特征的预测价值。
3. 存在价格、折扣、客户、时间和天气等多个维度。
4. 数据记录是订单商品明细，而不是每天每种商品的汇总销量。

因此，建议保留原始订单明细粒度，不要一开始就聚合成日销量。

### 2.2 预测目标：Quantity

**推荐作为唯一预测目标**

**选择：**

`Quantity`

即一条订单商品明细中消费者购买的商品数量。

其统计特征如下：

| 统计量 | 数值 |
| --- | --- |
| 均值 | 2.23 |
| 中位数 | 2 |
| 标准差 | 1.78 |
| 最小值 | 1 |
| 最大值 | 20 |
| 75% 分位数 | 3 |
| 偏度 | 2.61 |

购买数量分布明显右偏，存在少量大数量购买记录。

这也为后续研究异常值、模型误差和泛化能力提供了空间。

- Quantity 与 Units_Sold 并不完全相等，约 26.7% 的记录存在差异。
- Units_Sold 在 5,161 条记录中大于 Quantity，其余记录相等，没有小于 Quantity 的记录。
- Total_Bill 恰好满足 Selling_Price × Quantity。
- Profit 恰好满足 (Selling_Price - Cost_Price) × Quantity。

这说明 Quantity 是账单金额和利润计算所使用的数量，而 Units_Sold 是另一个不同的销售记录字段。

因此，使用 Quantity 作为预测目标时，应明确研究的是订单明细购买数量，而不是实际出库数量或门店日销量。

## 三、数据预处理方案

### 3.1 特征选择

原始数据有40个字段，但不能全部用于模型训练。

建议按照预测发生的时间点划分字段。

#### 第一类：候选输入特征

| 特征类别 | 字段 | 处理方式 |
| --- | --- | --- |
| 商品 | Product、Category | One-Hot Encoding |
| 客户 | Customer_Age、Gender、Segment | 数值保留、类别编码 |
| 客户 | Loyalty_Member | 二元编码 |
| 时间 | Year、Month、Day_of_Week、Weekend、Hour | 时间编码 |
| 环境 | Weather、Temperature、Season | 类别编码、数值保留 |
| 价格 | Unit_Price、Discount_Percentage | 数值标准化 |
| 促销 | Promotion_Applied、Promotion_Type | 类别编码 |
| 商品属性 | Shelf_Life_Days、Storage_Type、Perishability | 数值保留、类别编码 |
| 门店 | Store_ID | One-Hot Encoding |

#### 第二类：明确排除的字段

| 字段 | 排除原因 |
| --- | --- |
| Order_ID | 唯一订单标识符，没有直接业务意义 |
| Customer_ID | 原始客户标识符，不直接作为普通特征 |
| Date、Time | 转换成有意义的时间特征后排除原始字符串 |
| Total_Bill | 直接由预测目标和售价计算，存在严重数据泄漏 |
| Profit | 直接使用 Quantity 计算，存在严重数据泄漏 |
| Units_Sold | 销售结果字段，与目标高度关联 |
| Units_Produced | 生产结果，预测购买数量时不应使用 |
| Unsold_Units | 事后产生的库存结果 |
| Stock_Available | 时间点和定义不明确，暂不使用 |
| Waste_Pct | 事后产生的结果指标 |
| Payment_Method | 购买数量确定后才可能产生的信息 |
| Customer_Rating | 交易后的评价信息 |

另外，Selling_Price 可以由 Unit_Price 和 Discount_Percentage 推导。建议主实验使用原始单价和折扣率，避免重复输入高度相关的价格信息。

### 3.2 缺失值处理

实际 CSV 中：

| 字段 | 缺失数量 | 缺失比例 |
| --- | --- | --- |
| Festival | 16,006 | 82.84% |
| Promotion_Type | 13,826 | 71.56% |

处理建议：

- Promotion_Type：缺失与 Promotion_Applied = No 完全对应，可以填充为 No Promotion。
- Festival：填充为 Not Specified，暂时不要直接认定所有缺失都是非节日，需要结合数据字典确认。
- 其他字段：当前文件没有缺失值。

### 3.3 编码与标准化

建议采用 Scikit-learn Pipeline + ColumnTransformer。

| 特征类型 | 处理方法 |
| --- | --- |
| 数值特征 | StandardScaler |
| 无序类别特征 | OneHotEncoder |
| 二元特征 | 0/1 编码 |
| 时间周期特征 | 正余弦编码 |

例如，将星期转换为周期性特征：
$$
x_{\sin}=\sin(2\pi d/7)
$$
$$
x_{\cos}=\cos(2\pi d/7)
$$
这样可以避免把 Sunday 和 Monday 错误地看作距离很远的两个时间点。

注意：所有标准化、编码和特征选择参数都只能在训练数据上拟合。

### 3.4 数据集划分

考虑到数据包含完整的两年时间记录，建议使用时间顺序划分，而不是完全随机划分。

#### 时间划分方案

| 数据集 | 用途 | 记录数 | 日期范围 |
| --- | --- | ---: | --- |
| 训练集 | 模型训练 | 14,340 | 2023-01-01 至 2024-06-30 · 74.22% |
| 验证集 | 参数选择 | 2,533 | 2024-07-01 至 2024-09-30 · 13.11% |
| 测试集 | 最终评估 | 2,448 | 2024-10-01 至 2024-12-31 · 12.67% |

验证集用于模型和特征选择，测试集只在方案确定后进行一次最终评估。

这种划分更符合实际应用：使用过去的数据训练模型，预测未来订单。

## 四、回归模型构建

建议采用三个经典回归模型，形成从简单到复杂、从线性到非线性的比较体系。

### 4.1 模型选择

#### 模型一：Ridge Regression（岭回归）

线性基准模型

- 在线性回归基础上加入 L2 正则化。
- 缓解多重共线性和过拟合。
- 核心超参数：alpha。
- 适合分析特征与购买数量之间的线性关系。

#### 模型二：Decision Tree Regressor（决策树回归）

- 通过特征划分建立非线性预测规则。
- 能够学习价格、商品和客户特征之间的非线性关系。
- 核心超参数：max_depth、min_samples_split、min_samples_leaf。
- 便于理解模型如何进行决策。

#### 模型三：Random Forest Regressor（随机森林回归）

重点优化模型

- 通过 Bagging 集成多棵决策树。
- 利用随机采样和随机特征选择降低模型方差。
- 核心超参数：n_estimators、max_depth、min_samples_leaf、max_features。
- 适合处理复杂的非线性关系和特征交互。

此外，建议增加一个 DummyRegressor(strategy="median") 作为基准。

它始终预测训练集购买数量的中位数，可以回答一个很基本的问题：

复杂模型是否真的比不学习任何特征的简单预测方法更好？

### 4.2 模型训练方案

| 模型 | 主要预处理 | 优化方法 |
| --- | --- | --- |
| Ridge | One-Hot + StandardScaler | GridSearchCV |
| Decision Tree | One-Hot | GridSearchCV |
| Random Forest | One-Hot | RandomizedSearchCV |

建议初始超参数搜索范围：

#### Ridge

```text
alpha = [0.01, 0.1, 1, 10, 100]
```

#### Decision Tree

```text
max_depth = [3, 5, 8, 12, None]
min_samples_leaf = [2, 5, 10, 20]
```

#### Random Forest

```text
n_estimators = [100, 200, 300]
max_depth = [5, 10, 15, None]
min_samples_leaf = [2, 5, 10]
max_features = [0.5, 0.8, 1.0]
```

注意，以上是候选搜索范围，不是预先确定的最佳参数。

建议先在训练集上完成训练，再通过验证集选择参数。也可以在训练集内部采用时间顺序交叉验证。最终将训练集与验证集合并，重新训练选定模型，再使用测试集评估。

### 4.3 评价指标

建议使用三项主要指标：

| 指标 | 含义 | 优化方向 |
| --- | --- | --- |
| MAE | 平均绝对误差 | 越小越好 |
| RMSE | 均方根误差 | 越小越好 |
| R² | 决定系数 | 越大越好 |

其中：
$$
MAE=\frac{1}{n}\sum_{i=1}^{n}|y_i-\hat y_i|
$$
$$
RMSE=\sqrt{\frac{1}{n}\sum_{i=1}^{n}(y_i-\hat y_i)^2}
$$
$$
R^2=1-\frac{\sum_i(y_i-\hat y_i)^2}
{\sum_i(y_i-\bar y)^2}
$$
特别建议报告 MAE 和 RMSE 的差异：

- MAE 反映平均预测误差。
- RMSE 对少数大误差更加敏感。
- 如果 RMSE 明显大于 MAE，说明可能存在少数难以预测的大数量订单。

由于目标变量是整数，但回归模型输出可以是小数，评价时建议保留原始浮点预测值，不要先四舍五入再计算指标。

## 五、拓展实验：特征工程与特征选择

本组重点拓展方向
这一部分应该成为项目最有研究特色的内容。

不建议只做一次相关性热力图，然后展示模型特征重要性。我们应该设计能够回答明确问题的对照实验。

### 5.1 特征工程实验设计

建议设计四组特征方案。

| 方案 | 特征组成 | 研究目的 |
| --- | --- | --- |
| FE-0 | 基础商品、客户、价格、环境特征 | 建立基准 |
| FE-1 | FE-0 + 时间周期特征 | 验证时间特征价值 |
| FE-2 | FE-1 + 特征交互 | 验证组合关系价值 |
| FE-3 | FE-2 + 特征选择 | 验证冗余特征消除的效果 |

具体解释：

#### FE-0：基础特征

包含商品、客户、价格、促销、天气和门店等信息。

#### FE-1：时间特征工程

增加：

- Month 的周期性编码。
- Day_of_Week 的周期性编码。
- Hour 的周期性编码。
- 时间趋势变量。

例如月份的周期编码：
$$
Month_{\sin}=\sin(2\pi Month/12)
$$
$$
Month_{\cos}=\cos(2\pi Month/12)
$$
目的是让模型理解时间上的周期关系。

#### FE-2：特征交互

重点探索：

- Product × Season
- Product × Promotion_Type
- Product × Weekend
- Customer_Segment × Product

例如，不同商品在周末可能具有不同的购买数量变化规律。

可以使用类别组合特征（Feature Cross）实现，不建议直接对全部字段进行高阶多项式展开，否则特征维度可能急剧膨胀。

#### FE-3：特征选择

在 FE-2 基础上，进行特征筛选：

1. 相关性分析：识别数值特征之间的高度相关关系。
2. Mutual Information：评估特征与目标之间的统计依赖程度。
3. Permutation Importance：衡量打乱某个特征后模型性能的变化。
4. 基于重要性进行特征删减，再次训练模型。

建议比较保留全部特征和保留 Top-K 特征的效果，例如：
$$
K\in\{10,20,30,40\}
$$
这里的 K 指经过编码和特征构造后的特征数量，而不是原始 CSV 字段数量。

特征筛选必须仅使用训练集和验证集完成，不能根据测试集结果选择特征。

### 5.2 重点消融实验

为了避免实验只是不断增加特征，建议增加以下消融对照：

| 实验 | 特征变化 | 研究问题 |
| --- | --- | --- |
| A | 去除客户特征 | 客户画像是否有预测价值？ |
| B | 去除时间特征 | 时间信息是否重要？ |
| C | 去除价格和促销特征 | 价格策略是否影响购买数量？ |
| D | 去除天气特征 | 环境因素是否有贡献？ |
| E | 去除商品特征 | 商品身份是否是最重要的信息？ |

这组实验尤其重要。

例如，可能出现以下现象：

- 商品特征贡献最大，因为不同商品存在明显的购买数量差异。
- 客户特征能够提供一定补充信息。
- 时间周期特征有一定贡献，但并非所有商品都存在明显周期性。
- 天气特征对总体预测贡献较小。

以上都只是待验证的研究假设，不能预先当作实验结论。

### 5.3 如何判断特征工程是否有效？

建议制作一张统一实验表：

| 特征方案 | Ridge MAE | Tree MAE | RF MAE |
| --- | --- | --- | --- |
| FE-0 | 待实验 | 待实验 | 待实验 |
| FE-1 | 待实验 | 待实验 | 待实验 |
| FE-2 | 待实验 | 待实验 | 待实验 |
| FE-3 | 待实验 | 待实验 | 待实验 |

最终分析三个问题：

1. 增加特征是否真的提升预测效果？
2. 哪类模型更能利用特征交互？
3. 特征选择是否能减少复杂度，同时维持或提高泛化能力？

尤其值得关注的是：Ridge 和 Random Forest 可能对相同特征工程产生不同反应。线性模型可能更依赖显式的交互特征，而随机森林本身就能学习部分非线性关系和特征交互。

## 七、完整实验矩阵

将前面各部分整合，建议最终实验安排如下：

| 实验编号 | 实验名称 | 核心内容 | 必要性 |

这样可以控制工作量，同时保持实验逻辑完整。

| 4. 实验设计与结果 | 模型比较、指标分析 | 2 |
| 5. 模型优化 | 超参数调整、优化前后对比 | 2 |
| 6. 特征工程拓展 | 特征交互、消融、特征选择 | 3 |
| 7. 结果可视化与讨论 | 预测图、残差、重要性分析 | 1.5 |
| 8. 总结 | 结论、不足与改进方向 | 1 |
| 合计 |  | 14.5 |

报告应重点解释实验现象，而不是单纯罗列指标。

例如：

- 为什么随机森林优于 Ridge？
- 为什么加入时间特征后性能可能没有提升？
- 为什么某些特征具有较高相关性，却不一定有较高预测贡献？
- 为什么特征选择后模型性能可能反而下降？
- 为什么训练集效果很好，测试集却有所下降？

这些问题比单纯展示一个很高的 R² 更有价值。

## 十、项目执行计划

建议分为四个阶段。

1. 阶段一：数据探索与预处理
   基础阶段
   - 完成数据审计和字段筛选。
   - 明确预测目标与数据泄漏边界。
   - 完成训练、验证、测试集划分。
   - 建立统一预处理 Pipeline。
   交付物：数据分析 Notebook、预处理代码。

2. 阶段二：基础模型实验
   - 实现 Dummy、Ridge、Decision Tree、Random Forest。
   - 统一评价指标。
   - 完成初始模型比较。
   - 选择重点优化模型。
   交付物：基础实验结果表、模型对比图。

3. 阶段三：特征工程拓展
   项目重点
   - 周期性时间特征。
   - 特征交互。
   - 特征重要性分析。
   - 特征选择和消融实验。
   交付物：完整特征工程实验矩阵、分析图表。

4. 阶段四：最终评估与报告
   - 固定最佳实验方案。
   - 使用测试集进行最终评估。
   - 整理真实值与预测值对比图。
   - 完成报告和运行说明。
   交付物：实验报告、完整代码、运行 README。
